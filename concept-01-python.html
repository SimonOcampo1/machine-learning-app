{ Tema 01 · Piso }

Python esencial

No hace falta ser programador para hacer machine learning, pero sí hace falta leer código sin asustarse. Esto es lo mínimo, y alcanza para los veintitrés temas que siguen.

01

{ Por qué este lenguaje }

Python es el idioma del rubro

Casi todo el machine learning del mundo se escribe en Python. No porque sea el lenguaje más rápido —no lo es, ni cerca— sino porque las librerías que hacen el trabajo pesado están ahí: NumPy para las cuentas, scikit-learn para los modelos clásicos, PyTorch y TensorFlow para las redes neuronales. Elegir otro lenguaje es elegir escribir a mano lo que acá ya está escrito.

La consecuencia práctica es que vas a leer mucho más código del que vas a escribir. La mayoría de las veces tu trabajo va a ser armar cinco o seis líneas que le pasan tus datos a una función que otro escribió. Por eso este tema no busca que sepas programar: busca que puedas leer esas cinco líneas y entender exactamente qué hace cada una.

Todos los ejercicios de este sitio corren Python de verdad, dentro de tu navegador. No hay nada que instalar.

02

{ Lo primero }

Variables: nombres pegados a valores

Una variable es un nombre que apunta a un valor. El signo = no significa "es igual a" como en matemática: significa "de ahora en más, este nombre apunta a esto".

precio = 1500

Después de esa línea, cada vez que escribas precio, Python va a buscar el 1500. Y si más adelante escribís precio = 2000, el nombre se despega del 1500 y se pega al 2000. El valor viejo se pierde. Esto es lo que hace que la línea x = x + 1, que en matemática sería un absurdo, en programación sea perfectamente normal: "tomá lo que hay en x, sumale uno, y volvé a pegar el nombre x a ese resultado nuevo".

NotaPython distingue mayúsculas de minúsculas: precio y Precio son dos variables distintas. Es la fuente número uno de errores de tipeo.
03

{ Muchos valores juntos }

Listas

Una lista guarda varios valores en orden, entre corchetes y separados por comas. Es la estructura que más vas a usar: un conjunto de datos es, en el fondo, una lista de listas.

precios = [1500, 2000, 1800, 2400]

Para sacar un elemento se usan corchetes con su posición. Y acá viene lo único verdaderamente contraintuitivo de esta sección: se cuenta desde cero. El primer elemento es el 0, el segundo es el 1, y así. Una lista de cuatro elementos tiene posiciones 0, 1, 2 y 3, y pedir la posición 4 da error.

Dos operaciones que vas a usar a cada rato: len(precios) devuelve cuántos elementos hay (acá, 4), y precios.append(3000) agrega uno al final. También podés pedir un pedazo con dos puntos: precios[1:3] devuelve [2000, 1800] — desde la posición 1, hasta la 3 sin incluirla. Ese "sin incluirla" es la segunda fuente de confusión más común después del cero.

04

{ Repetir sin repetirse }

Bucles y la sangría que manda

Un bucle for recorre una lista y ejecuta lo mismo para cada elemento. La variable que va después del for es un nombre que vos elegís: en cada vuelta se pega a un elemento distinto.

for p in precios:
    print(p * 2)

Eso imprime cada precio duplicado, uno por línea. Fijate en dos cosas. Primero, los dos puntos al final de la línea del for. Segundo, y mucho más importante: la sangría.

En casi todos los lenguajes, la sangría es decoración. En Python es el código. Lo que está indentado abajo del for es lo que se repite; lo que vuelve al margen ya está afuera del bucle y se ejecuta una sola vez. No hay llaves ni palabras de cierre: la única forma de saber dónde termina un bloque es mirar dónde vuelve el margen.

El otro bloque indentado que vas a ver es el if, que ejecuta algo solo si una condición se cumple. Se lee casi como inglés: if precio > 2000: y abajo, indentado, lo que pasa en ese caso.

CuidadoUn solo = asigna, dos == comparan. if x = 5 es un error de sintaxis; if x == 5 es la pregunta "¿x vale 5?". Es el error de tipeo más frecuente de quien arranca.
05

{ Empaquetar una idea }

Funciones

Una función es un pedazo de código con nombre, al que le podés pasar valores y que te devuelve un resultado. Se define con def, y lo que devuelve sale por return.

def promedio(numeros):
    return sum(numeros) / len(numeros)

Definirla no hace nada todavía: es como escribir una receta. Recién cuando la llamás —promedio([1500, 2000, 1800])— se ejecuta y devuelve 1766.67.

La palabra return hace dos cosas a la vez: entrega el valor y termina la función ahí mismo. Cualquier línea que venga después no se ejecuta nunca. Y una función sin return devuelve None, que es el valor especial de Python para "nada": si alguna vez ves un None donde esperabas un número, casi siempre es un return olvidado.

06

{ Buscar por nombre }

Diccionarios

Una lista guarda cosas en orden y las buscás por posición. Un diccionario las guarda por etiqueta y las buscás por nombre. Se escribe con llaves, y cada entrada es clave: valor.

casa = {"m2": 85, "precio": 2400, "barrio": "Flores"}

Y se lee con corchetes, igual que una lista, pero pasando la clave en vez de un número: casa["m2"] devuelve 85. El orden acá no importa y no se usa nunca; lo que importa es el nombre.

Los vas a encontrar en todos lados: los resultados de un modelo, sus parámetros de configuración y la mayoría de las respuestas de librerías vienen como diccionarios. Cuando veas modelo.get_params() devolviendo algo con llaves y dos puntos, es esto.

ClaveLa regla rápida para elegir: si vas a recorrer todo en orden, lista. Si vas a buscar un valor puntual por su nombre, diccionario.

08

{ Errores frecuentes }

Lo que más se rompe al principio

TrampaContar desde uno. precios[1] no es el primer precio, es el segundo. Y en una lista de cuatro elementos, precios[4] no existe: tira IndexError. Si un bucle te falla justo en la última vuelta, casi siempre es esto.
TrampaMezclar tabs y espacios. Se ven idénticos en pantalla y Python los cuenta distinto, así que el error (IndentationError) señala una línea que a la vista está perfecta. Usá siempre espacios; cualquier editor lo hace solo.
Error clásicoModificar una lista mientras la recorrés. Si dentro de un for hacés append o borrás elementos de la misma lista que estás recorriendo, el bucle se saltea elementos o no termina nunca, porque las posiciones se corren debajo suyo mientras avanza. La solución es siempre la misma: armá una lista nueva con lo que querés conservar, en vez de tocar la original.
09

{ Síntesis }

Lo que hay que llevarse

Una variable es un nombre pegado a un valor, y = pega, no compara: comparar es ==. Una lista guarda valores en orden y se indexa desde cero, con los negativos contando desde el final. Un bucle for repite un bloque para cada elemento, y en Python la sangría no es estética: es lo único que define qué está adentro del bloque y qué está afuera. Una función empaqueta una idea con un nombre, recibe argumentos y devuelve un valor con return; sin return devuelve None. Un diccionario guarda valores por nombre en vez de por posición, y es la forma en que casi todas las librerías te devuelven sus resultados. Con eso alcanza para leer el código de los veintitrés temas que siguen. El próximo, NumPy, agrega la única estructura que falta: el array, que es una lista que sabe hacer cuentas sobre todos sus elementos a la vez.
