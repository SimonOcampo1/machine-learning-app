{ Tema 02 · Piso }

NumPy y pensar en vectores

El cambio mental más importante de esta fase: dejar de pensar "para cada dato, hacé esto" y empezar a pensar "hacé esto sobre todos los datos". Es lo que hace que el machine learning sea viable.

01

{ El problema }

Una lista no sabe hacer cuentas

En el tema anterior vimos que una lista guarda valores en orden. Lo que una lista no sabe hacer es operar sobre todos a la vez. Si tenés los precios de cuatro casas y querés subirlos todos un 10%, con listas hay que recorrerlas:

nuevos = []
for p in precios:
    nuevos.append(p * 1.1)

Funciona, y con cuatro casas no se nota nada. El problema aparece con las cantidades reales del rubro: un conjunto de datos chico tiene decenas de miles de filas, y entrenar un modelo implica recorrerlas cientos de veces. Ese bucle, escrito en Python puro, es entre cincuenta y cien veces más lento que lo que vamos a ver ahora, y esa diferencia es la que separa "entrena en dos minutos" de "entrena en tres horas".

Peor todavía, y esto pesa más que la velocidad: escribir bucles anidados para cada operación vuelve el código imposible de leer. La fórmula de la regresión lineal cabe en una línea; escrita con bucles ocupa quince y no se parece en nada a la fórmula.

02

{ La solución }

El array

NumPy es la librería que resuelve esto. Su estructura es el array: se parece a una lista, pero sabe hacer cuentas sobre todos sus elementos de una sola vez.

import numpy as np
precios = np.array([1500, 2000, 1800, 2400])
nuevos = precios * 1.1

Tres líneas, sin bucle, y el resultado es un array con los cuatro precios aumentados. Esa multiplicación se aplica a cada elemento por separado: es lo que se llama una operación vectorizada.

El import numpy as np de la primera línea es una convención universal: absolutamente todo el código de machine learning del mundo escribe np. No es obligatorio, pero escribir otra cosa es como hablar con acento raro.

NotaUn array tiene un solo tipo de dato para todos sus elementos, a diferencia de una lista, que puede mezclar números y textos. Esa restricción es justamente lo que le permite ser rápido: sabe de antemano cuánto ocupa cada elemento.
03

{ Dos dimensiones }

Filas, columnas y la forma

Hasta acá el array fue una fila de números. Pero los datos de verdad son tablas: una fila por observación, una columna por característica. Eso es un array de dos dimensiones, y se arma con una lista de listas.

X = np.array([[85, 3], [120, 4], [60, 2], [95, 3]])

Cuatro casas, dos características cada una: metros cuadrados y ambientes. La propiedad X.shape devuelve (4, 2): cuatro filas, dos columnas. Es lo primero que hay que mirar cuando algo no funciona, y vas a escribirlo cientos de veces.

La convención del rubro es tan firme que conviene aprenderla ya: la matriz de datos se llama X, en mayúscula, y el vector de respuestas se llama y, en minúscula. La mayúscula es porque es una matriz y la minúscula porque es un vector. Vas a ver modelo.fit(X, y) en todos los temas que siguen.

El axis del diagrama es el argumento que más confunde. X.mean() sin más promedia los ocho números juntos. X.mean(axis=0) devuelve dos números: el promedio de cada columna, o sea el m² promedio y los ambientes promedio. X.mean(axis=1) devuelve cuatro: el promedio de cada fila, que acá no significa nada útil.

ClaveLa regla para no equivocarse: axis nombra la dimensión que desaparece. Con axis=0 sobre una forma (4, 2), se colapsan las 4 filas y queda (2,). Con axis=1 se colapsan las 2 columnas y queda (4,).
04

{ Formas que no coinciden }

Broadcasting

Cuando escribiste precios * 1.1, un array de cuatro elementos se multiplicó por un solo número. Estrictamente, esas dos cosas no tienen la misma forma. NumPy lo resolvió estirando el 1.1 hasta cubrir los cuatro elementos, sin copiar nada en memoria. Eso es broadcasting.

Funciona también entre arrays. Si X tiene forma (4, 2) y le restás un array de forma (2,), NumPy repite ese par de valores en las cuatro filas. Esto no es una curiosidad: es exactamente la operación de estandarizar datos, que vas a hacer en casi todos los temas.

X_centrada = X - X.mean(axis=0)

Esa línea le resta a cada columna su propio promedio. Con bucles serían cuatro líneas y dos índices; acá es una, y se lee casi como la frase en castellano.

La regla formal es que las formas se comparan de derecha a izquierda y cada par de dimensiones tiene que ser igual o valer 1. En la práctica vas a usar dos casos: array con número, y matriz con fila. El resto conviene chequearlo con .shape antes de pelearse.

05

{ Elegir sin buscar }

Máscaras booleanas

La última herramienta imprescindible. Comparar un array con un número no devuelve True o False: devuelve un array de True y False, uno por elemento.

precios > 1900  →  [False, True, False, True]

Y ese array de booleanos se puede usar como índice, para quedarse solo con los elementos donde dio True:

caros = precios[precios > 1900]  →  [2000, 2400]

Se lee de adentro hacia afuera y termina sonando natural: "precios, donde precios sea mayor a 1900". Es la forma estándar de filtrar datos, y también de contar: como True vale 1, (precios > 1900).sum() devuelve 2, la cantidad de casos que cumplen. Ese truco de sumar booleanos aparece en todas las métricas de clasificación de la fase 3.

07

{ Errores frecuentes }

Lo que más se rompe

TrampaConfundir los ejes. axis=0 promedia hacia abajo, por columna; axis=1 promedia hacia el costado, por fila. La confusión no tira error: devuelve números plausibles pero equivocados, que es mucho peor. La regla del eje que desaparece es la que salva.
TrampaCreer que un corte es una copia. b = a[0:2] no copia: b es una ventana sobre la misma memoria, y modificar b modifica a. Es lo contrario de lo que hacen las listas de Python. Si querés una copia de verdad, a[0:2].copy().
Error clásicoDesalinear X e y. Si ordenás, filtrás o mezclás X sin aplicarle exactamente lo mismo a y, cada fila queda con la respuesta de otra casa. El código no falla, el modelo entrena igual, y las predicciones salen basura sin ninguna señal de que algo anduvo mal. Por eso lo estándar es filtrar con una misma máscara aplicada a los dos: X[m], y[m].
08

{ Síntesis }

Lo que hay que llevarse

Un array de NumPy es una lista que sabe hacer cuentas sobre todos sus elementos a la vez, sin bucles, y esa es la única forma de que el machine learning sea viable en Python. Los datos se organizan en una matriz X de forma (observaciones, características) y un vector y con la respuesta de cada fila; .shape es lo primero que hay que mirar cuando algo no cierra. El argumento axis nombra la dimensión que se colapsa, y confundirlo devuelve números plausibles y equivocados, no un error. Broadcasting estira automáticamente las formas que no coinciden, y es lo que permite escribir X - X.mean(axis=0) en una línea. Las máscaras booleanas filtran y cuentan sin recorrer nada. Con esto ya se puede leer el código de cualquier tema que siga; el próximo, álgebra lineal, le pone nombre matemático a las mismas operaciones que acabás de escribir.
