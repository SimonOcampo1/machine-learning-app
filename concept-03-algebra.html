{ Tema 03 · Piso }

Álgebra lineal mínima

En el tema anterior escribiste X * 1.1 y funcionó. Esto le pone nombre a lo que estabas haciendo, y agrega la única operación que todavía falta: la que es una predicción.

01

{ Cambio de nombre }

Vector y matriz: lo mismo que ya tenías

No hay nada nuevo que construir. Un vector es una lista de números, y ya la escribiste: np.array([85, 3]) es un vector de dos componentes. Una matriz es una tabla de números, y también la escribiste: la X de forma (4, 2) del tema anterior es una matriz de cuatro filas por dos columnas.

Lo que cambia es qué representan. En machine learning la convención es rígida y conviene fijarla ahora, porque no se va a mover en los veintiún temas que siguen:

Una fila

Un vector.

Una observación completa: esta casa, con todas sus características. 85 m² y 3 ambientes es el vector [85, 3].

Una columna

También un vector.

Una característica medida en todas las observaciones: los metros cuadrados de las cuatro casas.

La tabla entera

Una matriz.

Todas las observaciones con todas sus características. Es la X que se le pasa a cualquier modelo.

La palabra dimensión de un vector significa cuántos números tiene. Un vector de 2 dimensiones se puede dibujar en una hoja; uno de 3, en el espacio; uno de 500, no se puede dibujar y no importa, porque las cuentas son idénticas. Que un dataset "tenga muchas dimensiones" quiere decir, simplemente, que cada fila tiene muchas columnas.

02

{ Las dos fáciles }

Sumar y escalar

Dos vectores del mismo tamaño se suman componente a componente. [85, 3] + [10, 1] da [95, 4]. Si los tamaños no coinciden, la suma no existe y NumPy tira error: no hay ninguna interpretación razonable de sumar una casa con dos características a otra con cinco.

Multiplicar un vector por un solo número (que en este contexto se llama escalar) multiplica cada componente. [85, 3] × 2 da [170, 6]. Geométricamente estira o encoge el vector sin cambiarle la dirección; si el número es negativo, la da vuelta.

03

{ La operación que importa }

El producto punto

Esta es la que hay que entender de verdad. El producto punto entre dos vectores del mismo tamaño multiplica los pares que están en la misma posición y suma todo. El resultado no es un vector: es un solo número.

[85, 3] · [1200, 50000] = 85×1200 + 3×50000 = 252.000

Leelo despacio, porque acabás de ver una predicción. El primer vector es una casa: 85 m² y 3 ambientes. El segundo son los coeficientes de un modelo: 1200 pesos por metro cuadrado y 50.000 pesos por ambiente. El producto punto de los dos es el precio que ese modelo predice para esa casa.

Eso es todo lo que hace un modelo lineal. La regresión lineal del tema 09, la regresión múltiple del 10, la regresión logística del 12 y cada neurona de las redes del 22: todas calculan un producto punto entre las características de una observación y un vector de coeficientes. Lo único que cambia entre ellas es cómo se eligen esos coeficientes y qué se hace con el número que sale.

ClaveEl producto punto mide qué tan alineados están dos vectores. Si apuntan para el mismo lado da grande y positivo; si son perpendiculares da exactamente cero; si apuntan al revés da negativo. Esa lectura vuelve en el tema 16, cuando SVM use el cero para definir una frontera.
04

{ Todas las filas de una vez }

Matriz por vector

Un producto punto predice el precio de una casa. Si tenés cuatro, la reacción natural es un bucle. Pero ya sabemos del tema 02 que eso es lo que hay que evitar.

Multiplicar una matriz por un vector es exactamente eso, hecho de una sola vez: se toma cada fila de la matriz y se hace su producto punto con el vector. Con X de forma (4, 2) y un vector de coeficientes de forma (2,), el resultado es un vector de forma (4,): una predicción por casa.

predicciones = X @ beta

Esa línea es, literalmente, "aplicá el modelo a todo el dataset". Es la línea que está adentro de casi todas las librerías que vas a usar, y la razón por la que vale la pena haber leído hasta acá: X @ beta deja de ser un símbolo raro y pasa a leerse como una frase.

Las formas tienen que encajar, y la regla es una sola: el número de columnas del primero tiene que ser igual al número de filas del segundo. (4, 2) con (2,) funciona porque el 2 coincide, y el resultado se queda con lo de afuera: (4,). Si no coinciden, NumPy tira un error que menciona las dos formas, y ese error es tu amigo.

CuidadoEn NumPy, A * B y A @ B son cosas distintas. El asterisco multiplica elemento por elemento; la arroba hace el producto matricial. Con formas que casualmente encajan para las dos, el asterisco no da error: da otro resultado. Para modelos siempre es @.
05

{ Medir }

Norma: el largo de un vector

La norma de un vector es su largo. Se calcula elevando cada componente al cuadrado, sumando todo y sacando la raíz. Con dos componentes es exactamente el teorema de Pitágoras: el vector [3, 4] tiene norma 5.

‖v‖ = √(v₁² + v₂² + … + vₙ²)

Sirve para dos cosas que vas a usar mucho. La primera es medir distancia: la distancia entre dos puntos es la norma de su diferencia, ‖u − v‖. Ese es el corazón del tema 14, donde clasificar consiste en buscar los vecinos más cercanos, y del 20, donde agrupar consiste en asignar cada punto al centro más cercano.

La segunda es medir tamaño. Cuando en el tema 11 se hable de "castigar coeficientes grandes", lo que se va a castigar es la norma del vector de coeficientes. Ridge usa la suma de cuadrados, que es la norma de recién sin la raíz; Lasso usa la suma de los valores absolutos, que es otra norma. La diferencia entre esas dos formas de medir el mismo vector es la diferencia entre los dos métodos.

En NumPy: np.linalg.norm(v).

07

{ Errores frecuentes }

Lo que más se rompe

TrampaEsperar un vector donde sale un número. El producto punto de dos vectores devuelve un escalar, no un vector. Si escribiste u @ v y después intentás indexar el resultado con [0], Python te va a decir que un número no se puede indexar. La confusión viene de que * sí devuelve un vector.
TrampaDar vuelta el orden. X @ beta y beta @ X no son lo mismo, y a diferencia de la suma, el orden importa siempre en el producto matricial. Con formas (4,2) y (2,), el primero funciona y el segundo tira error, así que este al menos avisa.
Error clásicoUsar * creyendo que es producto matricial. Con un vector de coeficientes de forma (2,) y una matriz (4, 2), X * beta no da error: broadcasting multiplica cada fila componente a componente y devuelve una matriz (4, 2). Parece que anduvo. Pero te faltó sumar, así que tenés cuatro pares de números sueltos en vez de cuatro predicciones, y el código sigue corriendo con datos mal. Es el error silencioso de este tema.
08

{ Síntesis }

Lo que hay que llevarse

Un vector es una fila de datos y una matriz es la tabla completa; la dimensión de un vector es cuántos números tiene, y que sean quinientos no cambia ninguna cuenta. Sumar y escalar funcionan componente a componente y no tienen misterio. La operación que hay que entender de verdad es el producto punto: multiplicar par a par y sumar todo, para obtener un solo número, porque ese número es la predicción de un modelo lineal, y todos los modelos lineales del sitio hacen exactamente eso. Multiplicar una matriz por un vector aplica ese producto punto a todas las filas a la vez, y se escribe X @ beta, con arroba y no con asterisco: el asterisco no da error, da otra cosa. La norma es el largo de un vector, y sirve tanto para medir distancias entre puntos, que es lo que hacen KNN y k-means, como para medir el tamaño de un vector de coeficientes, que es lo que castiga la regularización. El próximo tema cierra la fase con lo mínimo de probabilidad y estadística, y ahí aparece Bayes, que es el resultado más contraintuitivo de toda esta fase.
