{ Tema 05 · Aprender de los datos }

Qué es machine learning

El piso ya está. Antes de entrenar el primer modelo hace falta una definición que no sea marketing: qué significa exactamente que una máquina aprenda, y cuándo conviene que no lo haga.

01

{ La definición }

Aprender, en un sentido preciso

La definición que se usa en el rubro es de Tom Mitchell y tiene la virtud de ser verificable: un programa aprende de la experiencia si su desempeño en una tarea mejora a medida que acumula más experiencia.

Las tres piezas hay que nombrarlas explícitamente, porque un proyecto que no puede completar las tres no está listo para empezar:

La tarea

Qué querés que haga.

Decidir si un mail es spam. Predecir el precio de una casa. Agrupar clientes parecidos.

La experiencia

De qué aprende.

Diez mil mails ya marcados. Las ventas de los últimos tres años. El historial de compras.

La medida

Cómo sabés si mejoró.

Porcentaje de mails bien clasificados. Error promedio en pesos. Y acá empiezan los problemas.

La tercera es la que se saltea todo el mundo y la que hunde proyectos. "Que ande bien" no es una medida. Sin un número que se pueda calcular antes de empezar, no hay forma de saber si el modelo nuevo es mejor que el viejo, ni de saber cuándo parar. El tema 13 está dedicado entero a elegir bien ese número, porque elegir mal es la forma más común de construir con confianza algo inútil.

02

{ El cambio de método }

Reglas escritas contra reglas inferidas

En programación tradicional, vos escribís las reglas. Para filtrar spam pondrías algo como: si dice "GRATIS" en mayúsculas, o si viene de un remitente desconocido con tres links, marcalo como spam.

Funciona un rato. Después alguien escribe "G R A T I S", y agregás una regla. Después "gr4tis", y agregás otra. A los seis meses tenés cuatrocientas reglas que se contradicen entre sí, nadie se anima a borrar ninguna, y el sistema sigue dejando pasar spam.

El machine learning da vuelta la dirección del trabajo. En vez de escribir las reglas, le das ejemplos con la respuesta puesta y el algoritmo infiere las reglas solo. Cuando aparece "gr4tis", no agregás una regla: agregás mails etiquetados y reentrenás.

ClaveDe ahí sale la consecuencia práctica más importante del rubro: tu modelo no puede ser mejor que tus datos. Si las etiquetas están mal, el modelo aprende a reproducir ese error con toda precisión, y ninguna elección de algoritmo lo arregla.
03

{ El mapa }

Las tres ramas

Todo lo que se llama machine learning cae en una de tres categorías, y lo único que las separa es qué le das al algoritmo.

Supervisado

Entra: ejemplos con la respuesta correcta.

Sale: una función que predice la respuesta de un ejemplo nuevo.

Es la rama más grande y la que cubren los temas 09 a 19 de este sitio.

No supervisado

Entra: ejemplos sin ninguna respuesta.

Sale: estructura que estaba escondida en los datos.

Agrupar o resumir. Temas 20 y 21. No hay con qué comparar, así que no hay una respuesta objetivamente correcta.

Por refuerzo

Entra: un entorno que premia y castiga.

Sale: una política: qué conviene hacer en cada situación.

Juegos y robótica. Este sitio no lo cubre, pero conviene saber que existe y por qué es distinto.

La pregunta que resuelve casi todos los casos es una sola: ¿tenés una columna con la respuesta? Si la tenés, es supervisado. Si no, es no supervisado. Y si no hay respuestas pero sí hay un premio que llega después de una secuencia de decisiones, es refuerzo.

04

{ Dentro de supervisado }

Regresión y clasificación

El aprendizaje supervisado se parte en dos según qué tipo de respuesta querés predecir.

Regresión predice un número que puede tomar cualquier valor intermedio: el precio de una casa, la temperatura de mañana, cuántos minutos va a tardar un envío. Clasificación predice a cuál de un conjunto de categorías pertenece algo: spam o no, qué dígito es, qué especie de flor.

El truco para no confundirse ya está en la página de temas, y es bueno: ¿la respuesta admite un punto y medio? Un precio de 1500,5 tiene sentido. Un "spam y medio" no. Si el valor intermedio significa algo, es regresión.

CuidadoUn número no garantiza regresión. Si las categorías son 1, 2 y 3 estrellas, son números pero el modelo no debería predecir 2,4 sin que eso signifique algo. Y al revés: una categoría con muchos niveles ordenados a veces conviene tratarla como número. El criterio no es el tipo de dato, es si la distancia entre dos valores significa algo.
05

{ La sección impopular }

Cuándo no usar machine learning

Un modelo es difícil de explicar, se degrada solo con el tiempo, necesita datos que hay que mantener, y falla de formas que nadie previó. Si una regla escrita a mano resuelve el problema, la regla gana siempre.

Casos concretos donde conviene no entrenar nada:

  • La regla existe y es exacta. Calcular el IVA es una multiplicación, no un problema de predicción. Suena obvio y sin embargo se ven modelos entrenados para esto.
  • No tenés datos suficientes. Con doscientas filas y treinta columnas, cualquier modelo va a encontrar patrones que son puro ruido. El tema 08 explica por qué.
  • Un error tiene consecuencias graves y no podés explicar la decisión. En crédito, salud o justicia, "el modelo dijo que no" no es una respuesta aceptable, y a veces es directamente ilegal.
  • El mundo cambia más rápido de lo que podés reentrenar. Un modelo entrenado con datos de hace dos años describe un mundo que ya no existe.

La versión corta: el machine learning sirve cuando el patrón existe, es demasiado complicado para escribirlo a mano, y tenés suficientes ejemplos de él. Si falta alguna de las tres, hay una solución más barata.

07

{ Errores frecuentes }

Lo que más se rompe

TrampaArrancar sin definir la medida de éxito. Si el número con el que vas a juzgar el modelo se elige después de ver los resultados, siempre vas a encontrar uno que te dé bien. Definilo antes de entrenar, por escrito.
TrampaConfundir correlación con causalidad. Un modelo encuentra que dos cosas van juntas, no que una cause la otra. Sirve perfecto para predecir y no sirve para decidir intervenciones: predecir quién va a cancelar el servicio no te dice qué hacer para que no cancele.
Error clásicoEntrenar sobre etiquetas mal puestas. Si el que etiquetó los mails se equivocó en el 15%, el modelo aprende ese 15% de error como si fuera la verdad, y va a alcanzar 85% de "acierto" contra las etiquetas reales sin que nada falle nunca. Ningún algoritmo, ninguna cantidad de datos y ninguna métrica lo detectan: el problema no está en el modelo, está en lo que le enseñaste. Mirar cien ejemplos a mano antes de entrenar es el uso más rentable de una hora en todo el proyecto.
08

{ Síntesis }

Lo que hay que llevarse

Un programa aprende si su desempeño en una tarea mejora con más experiencia, y las tres piezas de esa definición (tarea, experiencia y medida) hay que poder nombrarlas antes de empezar; la medida es la que se saltea todo el mundo y la que hunde proyectos. La diferencia con la programación tradicional es una inversión de entradas y salidas: en vez de escribir reglas para producir respuestas, das respuestas para producir reglas, y de ahí sale que el modelo nunca puede ser mejor que sus datos. Hay tres ramas y se distinguen por una sola pregunta: si tenés una columna con la respuesta es supervisado, si no la tenés es no supervisado, y si en cambio hay premios y castigos a lo largo de una secuencia es refuerzo. Dentro de supervisado, regresión predice un número donde los valores intermedios significan algo y clasificación predice una categoría donde no. Y la sección que conviene no olvidar es la última: si una regla escrita a mano resuelve el problema, la regla gana, porque un modelo se degrada solo, es difícil de explicar y falla de maneras que nadie previó. El próximo tema recorre el flujo de trabajo completo, y ahí aparece el dato incómodo de que limpiar datos se lleva la mayor parte del tiempo real.
