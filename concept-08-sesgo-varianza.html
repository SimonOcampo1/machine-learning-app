{ Tema 08 · Aprender de los datos }

Sesgo, varianza y overfitting

La tensión central de todo el machine learning, y el motivo por el que un modelo más potente empeora los resultados con una frecuencia que sorprende.

01

{ Dos formas de fallar }

Demasiado simple y demasiado complejo

Tenés diez puntos que siguen, más o menos, una curva suave, con algo de ruido encima. Vas a ajustarles un polinomio y podés elegir el grado.

Con grado 1 obtenés una recta. No importa cuántos datos le des: una recta no puede seguir una curva, y se va a equivocar sistemáticamente. Eso es underfitting: el modelo es demasiado rígido para la forma real del patrón.

Con grado 9 y diez puntos, el polinomio pasa exactamente por los diez. Error de entrenamiento: cero. Y entre punto y punto pega unos saltos absurdos, porque no aprendió la curva: memorizó los diez puntos, ruido incluido. Eso es overfitting.

Con grado 3 sigue la curva sin perseguir cada punto individual. No acierta perfecto en ninguno y acierta razonablemente en todos, incluidos los que todavía no vio.

02

{ Los nombres }

Sesgo y varianza

Esas dos formas de fallar tienen nombre técnico, y entenderlos como experimentos mentales repetidos es lo que los vuelve claros. Imaginá que pudieras conseguir muchos conjuntos de entrenamiento distintos del mismo fenómeno, y entrenar un modelo con cada uno.

Sesgo bias

Cuánto se equivoca el modelo en promedio, aun con todos los datos del mundo. Es error por rigidez: la forma que el modelo puede tomar no alcanza para la forma real del patrón.

Una recta ajustando una curva tiene sesgo alto, y agregar datos no lo baja.

Varianza variance

Cuánto cambia el modelo si le cambiás un poco los datos de entrenamiento. Es error por inestabilidad: el modelo está siguiendo ruido, y el ruido es distinto en cada muestra.

El polinomio de grado 9 tiene varianza altísima: sacá un punto y la curva cambia por completo.

La analogía del tiro al blanco ayuda. Sesgo alto es tirar siempre agrupado pero lejos del centro: consistente y equivocado. Varianza alta es tirar disperso alrededor del centro: en promedio bien, pero ningún tiro confiable.

El error total de un modelo se descompone en tres partes: sesgo, varianza, y un ruido irreducible que viene de los datos mismos y que ningún modelo puede eliminar. Esa tercera parte es importante recordarla, porque marca el piso: si dos casas idénticas se vendieron a precios distintos, ningún modelo va a poder acertarles a las dos.

03

{ El compromiso }

Por qué el error tiene forma de U

Acá está la parte incómoda: bajar uno sube el otro. Un modelo más flexible se adapta mejor al patrón real (baja el sesgo) pero también se adapta mejor al ruido (sube la varianza). Un modelo más rígido hace lo contrario.

Como el error total es la suma, y una parte baja mientras la otra sube, la suma tiene forma de U. Existe un punto de complejidad óptimo, y pasarse es tan malo como quedarse corto.

Clave"Complejidad" no es una sola perilla: es la profundidad de un árbol, el grado de un polinomio, la cantidad de vecinos en KNN (al revés: menos vecinos, más complejo), el alpha de Ridge, la cantidad de capas de una red. Todos esos hiperparámetros se eligen con validación cruzada, que es exactamente lo que hace el tema anterior.
04

{ El diagnóstico }

Dos números te dicen dónde estás

Esta es la parte más práctica del tema y conviene memorizarla. Calculás el error sobre entrenamiento y sobre validación, y los mirás juntos:

Error en trainError en validaciónDiagnósticoQué hacer
altoaltounderfittingmodelo más complejo, más características
bajoaltooverfittingregularizar, simplificar, más datos
bajobajobiennada, ya está
altobajoalgo está malrevisar el código, no es un caso real

La cuarta fila casi nunca es un modelo raro: es un bug. Un corte mal hecho, un conjunto de validación más fácil que el de entrenamiento, o una métrica calculada sobre el conjunto equivocado.

La distancia entre los dos errores se llama brecha de generalización, y es la medida directa del overfitting. Un modelo con 0.98 en train y 0.72 en validación tiene una brecha enorme; uno con 0.84 y 0.82 está sano aunque su número absoluto sea más bajo, y casi siempre es el que conviene poner en producción.

05

{ La herramienta }

Curvas de aprendizaje

Una curva de aprendizaje grafica los dos errores en función de cuántos datos de entrenamiento usás. Sirve para responder una pregunta concreta y cara: ¿conviene salir a conseguir más datos?

Si las dos curvas convergen y se juntan en un valor alto, tenés sesgo alto: el modelo ya aprendió todo lo que su forma le permite, y más datos no van a mover nada. Hay que cambiar de modelo.

Si quedan separadas, con el error de entrenamiento bajo y el de validación alto y todavía bajando, tenés varianza alta: más datos sí van a ayudar, porque le hacen más difícil memorizar.

Es la diferencia entre gastar tres meses etiquetando datos que no van a servir para nada, y gastarlos en lo único que faltaba.

07

{ Errores frecuentes }

Lo que más se rompe

TrampaCreer que más complejo es mejor. Cambiar una regresión lineal por un boosting de mil árboles sobre doscientas filas casi siempre empeora los resultados. La complejidad del modelo tiene que ir con la cantidad de datos, no con las ganas.
TrampaCombatir overfitting con más características. Es el reflejo equivocado: agregar columnas sube la varianza. Contra overfitting va menos complejidad, más regularización o más filas.
Error clásicoMirar solo el error de validación y no la brecha. Entre un modelo con 0.86 en validación y brecha de 0.13, y otro con 0.84 y brecha de 0.02, el reflejo es quedarse con el primero. Pero esa brecha grande significa que está siguiendo ruido, y en producción los datos traen ruido nuevo: el 0.86 no se sostiene. El número de validación sale bien, la decisión sale mal, y el problema recién aparece semanas después con datos reales.
08

{ Síntesis }

Lo que hay que llevarse

Hay dos formas de fallar: underfitting, cuando el modelo es demasiado rígido para el patrón real, y overfitting, cuando es tan flexible que memoriza el ruido junto con la señal. Sus nombres técnicos son sesgo y varianza: el sesgo es cuánto te equivocás en promedio aunque tengas todos los datos del mundo, y la varianza es cuánto cambia el modelo si le cambiás un poco los datos. Bajar uno sube el otro, así que el error total tiene forma de U y existe un punto de complejidad óptimo que se elige con validación cruzada. El diagnóstico práctico son dos números: los dos errores altos es underfitting, train bajo y validación alto es overfitting, y la distancia entre ambos, la brecha de generalización, es la medida directa de cuánto está memorizando. Un modelo con número absoluto un poco más bajo y brecha chica casi siempre le gana en producción a uno con número alto y brecha grande. Y las curvas de aprendizaje responden si conviene conseguir más datos: si las dos curvas ya convergieron, no; si siguen separadas, sí. Con esto cierra la fase 1 y el vocabulario está completo. La fase 2 arranca entrenando el primer modelo de verdad: la regresión lineal, que es el ejemplo canónico de sesgo alto y varianza baja.
