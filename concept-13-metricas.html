{ Tema 13 · Clasificación }

Métricas de clasificación

El tema 05 prometió que elegir la medida de éxito era lo que hunde proyectos. Este es ese tema: cómo un modelo con 99,5% de aciertos puede ser completamente inútil.

01

{ El problema }

La exactitud miente

La exactitud (o accuracy) es la fracción de predicciones correctas sobre el total. Es la métrica que todo el mundo usa por defecto, y es la correcta cuando las clases están razonablemente balanceadas y los dos tipos de error cuestan parecido.

Fuera de esas dos condiciones, engaña. Ya lo viste en el tema 05: sobre 10.000 transacciones con 50 fraudes, el modelo que dice siempre "no es fraude" alcanza 99,5% de exactitud y no detecta un solo fraude. Es literalmente el peor modelo posible para la tarea, y su métrica lo felicita.

El problema de fondo es que la exactitud mete todos los errores en la misma bolsa, y en casi ningún problema real los dos errores cuestan lo mismo. Rechazar una transacción legítima molesta a un cliente; dejar pasar un fraude cuesta plata. Marcar un mail bueno como spam puede hacerte perder una oferta de trabajo; dejar pasar un spam es una molestia de dos segundos.

Para hablar de eso hace falta separar los errores por tipo, y para eso está la herramienta central del tema.

02

{ La herramienta }

La matriz de confusión

Es una tabla de dos por dos que cruza lo que el modelo predijo con lo que realmente era. Todas las métricas que siguen salen de estas cuatro celdas, así que vale la pena mirarla hasta que se lea sola.

Los dos errores tienen nombres del mundo real que ayudan a no confundirlos. Un falso positivo es una falsa alarma. Un falso negativo es algo que se te pasó.

La exactitud es la diagonal dividida por el total. Y ahí se ve por qué falla: si los verdaderos negativos son 9.950 y todo lo demás son decenas, esa celda gigante domina la fracción y las otras tres dejan de influir.

03

{ Las dos que importan }

Precisión y recall

En vez de una fracción sobre el total, estas dos miran una fila y una columna de la matriz.

Precisión

De todo lo que el modelo marcó como positivo, ¿qué fracción lo era de verdad?

VP / (VP + FP). Responde "cuando este modelo dice que sí, ¿le puedo creer?". Es la fila de "dijo sí".

Recall

De todo lo que realmente era positivo, ¿qué fracción encontró el modelo?

VP / (VP + FN). Responde "¿cuánto se le escapa?". Es la columna de "era positivo".

Y acá está el punto: tirar de una baja la otra, y lo que las mueve es el umbral del tema 12. Subir el umbral hace que el modelo solo acuse cuando está muy seguro: menos falsas alarmas, más precisión, pero se le escapan más casos y baja el recall. Bajarlo hace lo contrario.

Cuál priorizar no lo decide el modelo, lo decide el problema:

Filtro de spam

Prioridad: precisión.

Un mail importante mandado a la basura es un desastre; un spam en la bandeja es una molestia de dos segundos. Conviene ser conservador para acusar.

Detección de cáncer

Prioridad: recall.

Una falsa alarma cuesta un estudio adicional; un caso que se pasa puede costar una vida. Conviene marcar de más y descartar después.

Búsqueda de documentos

Depende del uso.

Para una búsqueda casual importa la precisión de los primeros resultados. Para una revisión legal, donde no podés perderte nada, importa el recall.

Cuando hace falta un solo número, se usa el F1, que combina los dos con una media armónica. La media armónica castiga los desequilibrios: con precisión 1.0 y recall 0.0, el promedio común daría 0.5 y el F1 da 0. Eso es lo que se quiere, porque un modelo que nunca acusa no sirve por más preciso que sea cuando lo hace.

04

{ Sin elegir umbral }

La curva ROC y el AUC

Todo lo anterior depende de un umbral fijo. Pero el umbral es una decisión posterior, y a veces querés comparar dos modelos sin haberla tomado todavía.

La curva ROC resuelve eso: barre todos los umbrales posibles y, para cada uno, grafica cuántos positivos reales agarra (el recall) contra cuántas falsas alarmas produce. Un modelo que separa bien las clases sube rápido por la izquierda: consigue mucho recall con pocas falsas alarmas. Uno que no distingue nada da una diagonal, que es lo que produce el azar.

El AUC es el área bajo esa curva, un número entre 0 y 1. Vale 0.5 para un modelo que tira una moneda y 1.0 para uno perfecto. Tiene una interpretación linda: es la probabilidad de que, tomando un positivo y un negativo al azar, el modelo le dé más puntaje al positivo.

CuidadoEl AUC también se pone optimista con clases muy desbalanceadas, porque su eje de falsas alarmas se divide por la cantidad enorme de negativos y casi no se mueve. Cuando la clase positiva es muy rara, la curva de precisión contra recall es más informativa.

06

{ Errores frecuentes }

Lo que más se rompe

TrampaReportar exactitud con clases desbalanceadas. Es el error de este tema. Antes de mirar cualquier métrica, mirá qué proporción tiene cada clase, y calculá cuánta exactitud saca el modelo que dice siempre la clase mayoritaria.
TrampaConfundir precisión con recall. Las dos tienen los verdaderos positivos arriba y se distinguen por el denominador. Precisión divide por lo que el modelo marcó; recall, por lo que realmente había. La pregunta que las separa: "¿le creo cuando dice que sí?" contra "¿cuánto se le escapa?".
Error clásicoOptimizar una métrica que no es la del problema. Un equipo puede pasar semanas subiendo el F1 de 0.71 a 0.78 cuando el negocio necesitaba recall alto porque un caso perdido cuesta cien veces más que una falsa alarma. Todo el proceso funciona, los números mejoran, los informes se ven bien, y el modelo que se elige es el equivocado. La métrica se define en la etapa 1 del flujo, hablando con quien va a usar el modelo, y no se cambia después de ver los resultados.
07

{ Síntesis }

Lo que hay que llevarse

La exactitud sirve solo cuando las clases están balanceadas y los dos errores cuestan parecido; fuera de ahí, un modelo que nunca detecta nada puede lucir 99,5%. La matriz de confusión separa los dos tipos de error, que casi nunca valen lo mismo: un falso positivo es una falsa alarma y un falso negativo es algo que se te pasó. Precisión responde si le podés creer al modelo cuando dice que sí, y recall responde cuánto se le escapa; las dos comparten numerador y se distinguen por el denominador. Moverse entre ellas es mover el umbral, y cuál priorizar lo decide el problema, no el modelo: precisión para spam, recall para diagnóstico. El F1 las resume en un número y castiga los desequilibrios más de lo que lo haría un promedio común. La curva ROC compara modelos sin fijar umbral y su área, el AUC, es la probabilidad de rankear bien un positivo contra un negativo al azar, aunque con clases muy raras conviene mirar precisión contra recall. Y lo que hay que evitar por encima de todo es optimizar una métrica que no es la del problema, porque ahí todo funciona y la decisión igual sale mal.
